# SSPathNet on PlantVillage: a controlled study

Code, raw results and analysis scripts for the paper

> **Does Architectural Novelty Pay Off on a Saturated Benchmark? A Controlled Study of a Spectro-Spatial Hybrid Network for Plant Disease Classification**
> [Authors] - [Journal, year] - [DOI / preprint link]

We designed **SSPathNet** (9.80 M parameters), a hybrid network built around three ideas - a dual-stream
chromatic-frequency input (continuous HSV + block-DCT), deformable-inception / windowed cross-attention blocks, and gated
cross-layer aggregation with a center-constrained head - and tested it against four compact CNNs and nine one-factor
ablations, all **trained from scratch with one identical pipeline** on the 54,305-image, 38-class PlantVillage colour set.

## Headline findings (this is a negative result)

| | |
|---|---|
| **Accuracy** | SSPathNet reaches **99.40 %** (95 % CI 99.21-99.54; 5-fold CV 99.49 +- 0.18 %). It does **not** beat from-scratch ResNet-18 / EfficientNet-B0 / DenseNet-121 (99.71-99.75 %). |
| **Ablations** | None of the nine ablations gives a statistically reliable accuracy gain after multiplicity correction. TCFA does not beat plain concatenation; center loss and the adaptive activation show no benefit. |
| **DCT stream** | Lowers clean accuracy by 0.23-0.45 pp and makes every model that contains it collapse under Gaussian noise (sigma = 0.08): **8-19 %** accuracy, versus **85-87 %** for the two variants without it. |
| **Efficiency** | Parameters/FLOPs do not predict speed: SSPathNet and ResNet-18 have similar FLOPs, yet ResNet-18 is 4.1x faster in throughput and ~13x lower in batch-1 latency. Removing deformable sampling halves latency at no accuracy cost. |
| **Grad-CAM** | Activations frequently fall on background / leaf margins rather than lesions (qualitative, 12 images). |

| Model (from scratch, fixed split, n_test = 8,146) | Params (M) | Test acc. % (95 % CI) | Errors | Macro-F1 % |
|---|---|---|---|---|
| SSPathNet | 9.80 | 99.40 (99.21-99.54) | 49 | 99.08 |
| MobileNetV2 | 2.27 | 99.51 (99.33-99.64) | 40 | 99.38 |
| ResNet-18 | 11.20 | 99.71 (99.56-99.80) | 24 | 99.66 |

limitations (single seed per configuration, one laboratory dataset, unpaired tests, no cross-dataset evaluation).

## Repository layout

```
scripts/
  plantvillage_part1.py    SSPathNet main run + Grad-CAM + robustness, 4 baselines, 5-fold CV   (one Kaggle session, ~8.9 h on a T4)
  plantvillage_part2.py    full-model reference A0 + ablations A1-A9 + robustness               (one Kaggle session, ~10.5 h on a T4)
analysis/
  compute_tables.py        regenerates Tables 4-8 (+ robustness) with Wilson CIs, z-tests, Bonferroni flags
  make_figures.py          regenerates Figures 1-5 from the stored results
results/
  part1/, part2/           the exact outputs of the two Kaggle sessions (results.json, summary.csv, log.txt,
                           per-run history, confusion matrices, classification reports, curves, Grad-CAM)
  tables/                  CSV/Markdown tables generated by analysis/compute_tables.py
figures/                   Figures 1-6 of the paper (file numbers = paper numbers)
tests/                     30 unit/consistency tests (CPU, ~1 min, no dataset needed)
docs/
  REPRODUCING.md           step-by-step reproduction guide, timing, determinism notes
  ARCHITECTURE.md          paper concept -> class/function map
```

The two scripts are deliberately **self-contained** (the model/engine section is duplicated) so that each can run alone
in a separate 12-hour Kaggle session; a test asserts that the data-split code is identical in both.

## Quick start

```bash
# verify everything on a CPU in ~1 minute (no dataset required)
pip install -r requirements-dev.txt
pytest -q tests

# regenerate the paper's tables and figures from the stored results
python analysis/compute_tables.py
python analysis/make_figures.py
```

To re-run the experiments, see [`docs/REPRODUCING.md`](docs/REPRODUCING.md). In short: add the Kaggle dataset
`abdallahalidev/plantvillage-dataset` to a notebook with a **GPU T4**, paste a script, run it. Set `SMOKE_TEST = True`
first for a 5-minute check.

## Experimental protocol in brief

* **Data:** PlantVillage colour set, resized to 160 x 160; stratified 70/15/15 split (38,013 / 8,146 / 8,146), seed 42;
  stratified 5-fold CV for SSPathNet (90/10 train/val inside each training part). Checkpoint = best validation epoch;
  the test set is evaluated once.
* **Training (all models):** AdamW (lr 1e-3, weight decay 0.05), 30 epochs, batch 128, 2 warm-up epochs + cosine decay,
  label smoothing 0.1, fp16 AMP, GPU augmentation, random initialisation. No hyper-parameter was tuned.
* **Evaluation:** accuracy with Wilson 95 % CIs, macro-F1, Cohen's kappa, MCC; efficiency on the T4 (throughput at batch
  128, latency at batch 1, forward FLOPs); eight synthetic distribution shifts; Grad-CAM on stage-3 features.
* **Environment of the reported runs:** Kaggle, Tesla T4, `torch 2.10.0+cu128`, dataset folder
  `abdallahalidev/plantvillage-dataset/color`.

## Data

The dataset is **not** redistributed here. PlantVillage: Hughes & Salathe (2015), arXiv:1511.08060. We used the Kaggle

## Caveats you should know before reusing the results

* Each configuration was trained **once** (except SSPathNet, which also has 5-fold CV). Differences below ~0.2
  percentage points are within noise on this benchmark.
* Per-image predictions and model weights were not saved, so paired significance tests and Grad-CAM on other models
  cannot be reproduced from this repository.
* PlantVillage contains several images per leaf and class-correlated backgrounds; absolute accuracies may be
  optimistic and do not transfer to field images. A cross-dataset module exists in `plantvillage_part2.py`
  (`CROSS_DATASET_PATH`, e.g. PlantDoc) but was **not** run for the paper.
* Latency figures describe our PyTorch implementation (deformable sampling via `grid_sample`) on a T4, not the
  deformable convolution in general.
